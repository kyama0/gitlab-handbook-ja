# 定期翻訳バッチ

このファイルは、アプリのスケジュールから実行する翻訳作業 1 回分の指示です。
実行日時はアプリ側で毎日 06:00（Asia/Tokyo）に設定します。

## 実行指示

未マージの翻訳 PR を確認し、引き継げる PR があれば、その作業を優先してください。
引き継ぐ PR がない場合は、`$translate-batch` を使い、新しい翻訳バッチを 1 つ実行してください。
1 回の実行では、既存 PR 1 件の引き継ぎ、または新規バッチ 1 件を扱ってください。

リポジトリルートを基準に、以下のファイルを読んで従ってください。

- `AGENTS.md`
- `CLAUDE.md`
- `.agents/skills/translate-batch/SKILL.md`
- `.claude/translation-glossary.md`

新規バッチはスキルに従い、upstream 同期、翻訳、manifest 更新、検証、PR 作成、レビュー対応、条件を満たした後のマージまで行ってください。
既存 PR は、残っている翻訳・manifest 更新・検証を補完し、スキルのステップ 8 に従ってレビュー対応とマージまで進めてください。
実翻訳とレビューには、スキルで指定された Codex custom agent を使ってください。

## 未マージ PR の確認と引き継ぎ

新規バッチの upstream 同期や pending 判定より先に、`kyama0/gitlab-handbook-ja` の open PR を全件確認してください。ページネーションを使い、作成者で絞り込まず、draft PR も含めてください。
タイトル、ブランチ名、変更ファイル、PR 本文から翻訳バッチや翻訳レビュー修正の PR を特定してください。`translation/batch-*` 以外の名前や、別のエージェントが作成した PR も対象に含めてください。
翻訳と関係のない PR は対象外です。

各候補の最新 head、base、コメント、未解決レビュースレッド、CI、競合、draft の理由を確認し、何が未完了かを把握してください。
他のエージェントが作業中と明示している場合や、確認中にも head が更新されている場合は同時編集を避け、理由を記録して次の候補を確認してください。
明示的な保留や外部対応待ちで進められない PR も理由を記録し、引き継いで進められる PR のうち作成日時が最も古いものを 1 件選んでください。

選んだ PR の修正は、スキルのステップ 8-3 に従い、専用の新しい一時ディレクトリに clone して既存の head branch 上で行ってください。別の作業者が使っている clone や worktree は削除・上書きしないでください。
既存のコミットと有効な修正を保持し、PR が記録している upstream SHA の原文と manifest を照合して不足分を補完してください。新規バッチ用の upstream 同期で、既存 PR の翻訳根拠を一律に更新しないでください。
既存の PR と head branch を使って修正を push し、指摘への返信、スレッドの解決、必要な再レビュー依頼、競合解消を行ってください。同じ内容の PR を作り直さないでください。
draft は未完了部分を補完した後にレビュー可能な状態へ変更してください。マージ前には最新 head の CI とレビュー状況を再取得し、スキルで定めるマージ条件を満たしていることを確認してください。

既存 PR を引き継いだ回は、その対応結果を報告して終了してください。
引き継ぐ PR がなく新規バッチへ進む場合も、未マージの翻訳 PR がすでに扱っているファイルとの重複を避けて対象を選んでください。

## 作業場所とブランチ

状態確認と新規バッチの作業場所は、アプリが用意した worktree を使ってください。既存 PR の修正場所は、上記の専用 clone を使ってください。
スキル内の旧固定パス `/home/yamazaki/projects/gitlab-handbook-ja` は使わず、実行中の worktree または専用 clone のリポジトリルートを使ってください。
既存の無関係な変更は保持してください。

新規バッチは、fetch した最新の `origin/main` から `translation/batch-YYYY-MM-DD-N` ブランチを作成してください。日付は日本時間を使い、番号は既存ブランチと重複しないものを選んでください。
他の worktree で使用中の `main` に checkout せず、実行中の worktree で `origin/main` を起点にバッチブランチを作成してください。
新規 PR の base は `main` としてください。

## 終了条件と報告

新規翻訳の pending がゼロでも、未マージ PR の確認と引き継ぎは行ってください。
引き継ぐ PR がなく、重複を除いた新規バッチの対象もない場合は、スキルで指定された検証を行い、PR を作らず終了してください。
既存 PR または新規バッチ 1 件の対応が完了したら終了し、続けて次の PR やバッチに着手しないでください。
Slack 通知は不要です。

最後に、既存 PR の引き継ぎか新規作成か、PR URL、今回の翻訳・更新件数、manifest entries の差分、検証結果、レビュー対応概要、マージ状況を簡潔に報告してください。
対象にしなかった未マージの翻訳 PR があれば、その URL と理由も報告してください。
未完了の場合は、その理由と残っている作業も報告してください。
