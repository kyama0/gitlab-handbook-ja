## Infrastructure 面接の準備方法に関するヒント {#tips-on-how-to-prepare-for-infrastructure-interviews}

GitLab の Infrastructure 部門のロールの面接はどのようなものでしょうか？採用ステージのいくつかのヒントと一般的なガイドラインを以下に示します:

### 1. 応募 {#1-application}

GitLab のロールに応募する際は、注目してもらえるように、自分のスキルと経験をハイライトする履歴書をアップロードしてください！ロールの説明を注意深く確認し、技術的なスキルだけでなく、ロールへの期待値の観点でも自分に合っているかを理解してください。

希望する場合は、ハンドブックで Infrastructure 部門とそのさまざまなサブ部門についてさらに学ぶことができます。グループページではチームのミッション、ターゲット、チームメンバー、業務へのアプローチが紹介されています。

[GitLab の Infrastructure](/handbook/engineering/infrastructure/)

- [SaaS Platforms](/handbook/engineering/infrastructure-platforms/)
  - [Delivery Group](/handbook/engineering/infrastructure-platforms/gitlab-delivery/delivery/)
  - [Dedicated Group](/handbook/engineering/infrastructure-platforms/gitlab-dedicated/)
  - [Production Engineering Group](/handbook/engineering/infrastructure-platforms/production-engineering/)

うまく書かれた履歴書または詳細な LinkedIn プロフィールは、このロールに選ばれる可能性を高めます。要件を注意深く読み、それらの特定領域のいくつかが履歴書／LinkedIn プロフィールに明記されていることを確認してください。Infrastructure Engineering では、以下の経験／知識に特に注目しています:

- Linux システム管理
- CI/CD
- Ruby や Go などの言語でのプログラミング／スクリプティング経験
- モニタリングとオブザーバビリティ
- クラウド技術およびコンテナオーケストレーション
- オンコールおよびインシデント管理

要件に記載された希望分野すべての経験がなくても心配ありません！それでも応募することをお勧めします。私たちは上記の多様な経験を持つ候補者を探しています。
私たちはアクセシブルで包括的な面接体験を作ることを大切にしています。応募時に、採用および面接プロセスをサポートするために調整できることがあれば、お知らせください。

さて、ワクワクする時間です！次のリンクは、私たちの会社とロールをさらに理解するのに役立つかもしれません:

- バリュー
- [GitLab の企業文化](/handbook/company/culture/)
- [オールリモート環境におけるインフォーマルコミュニケーション](/handbook/company/culture/all-remote/informal-communication/)
- [インシデント管理](/handbook/engineering/infrastructure-platforms/incident-management/)

### **2. Recruiter との 30 分間のスクリーニング通話** {#2-30-minute-screening-call-with-a-recruiter}

この通話の目的は、あなた、あなたの期待、そしてあなたの経験についてもっと学ぶことです。私たちの側では、次の点でどれだけ合致しているかを学ぼうとしています: あなたが GitLab に参加した場合に、私たちがあなたの成長と願望をサポートできるか；あなたの技術的および対人スキルが Infrastructure と GitLab のニーズにどのように合致するか；私たちがあなたの期待にどう応えられるか。

これはあなたの職務経験と、私たちの GitLab Infrastructure 部門への参加動機についてもっと学びたい一般的な会話ですが、いくつかの技術的な質問も期待してください。また、採用条件を満たしているかどうかと、入社可能な時期についても話し合います。

私たちへの質問の準備を忘れないでください、私たちは質問が大好きです！これは次のステップで起こるすべての面接にも当てはまります。Infrastructure や GitLab に関連することなら何でも遠慮なく聞いてください。
スクリーニング通話から 3 営業日以内にメールでフィードバックを受け取ることが期待できます。

### 3. Infrastructure チームメンバーとの 90 分間の技術面接 {#3-90-minute-technical-interview-with-a-member-of-the-infrastructure-team}

合格した候補者は次のステップに進みます: 技術面接。技術面接は応募しているチームとポジションによって異なります。必要に応じて、このラウンドの前に何を期待し何を準備するかについて詳細情報を共有します。準備作業がある場合は、約 1 時間までです。

技術面接には GitLab アカウントが必要です。まだ GitLab に慣れていない場合は、面接の前に GitLab で実際に試してみることをお勧めします。一般的な紹介については [GitLab の紹介](https://docs.gitlab.com/ee/#new-to-git-and-gitlab)を参照してください。アカウントがない場合は、[サインアップページ](https://gitlab.com/users/sign_up)で作成できます。

面接には必要ありませんが、次のリンクは Infrastructure チームの責任についてもう少し理解するのに役立ちます:

- [インシデント管理](/handbook/engineering/infrastructure-platforms/incident-management/)
- [変更管理](/handbook/engineering/infrastructure-platforms/change-management/)
- [プロダクションアーキテクチャ](/handbook/engineering/infrastructure-platforms/production/architecture/)
- [Infrastructure のランブック](https://gitlab.com/gitlab-com/runbooks)
- [本番環境への準備状況](/handbook/engineering/infrastructure-platforms/production/readiness.md)
- [GitLab.com の解決済み・未解決インシデント](https://gitlab.com/gitlab-com/gl-infra/production/-/issues/?sort=updated_desc&state=all&label_name%5B%5D=incident&first_page_size=20)

面接するチームについてもっと理解できるよう、各チーム面接の前にインタビュアー（GitLab プロフィールを含む）に関する情報を Guide 経由で共有します。

タスクの指示／最終目標が明確でない場合は、遠慮なく確認を求めてください。それに加えて、私たちのエンジニアへの質問をいつでも準備してください！技術面接から 3 営業日以内にメールでフィードバックを受け取ることが期待できます。

### 4. 60 分間の Hiring Manager 面接 {#4-60-minute-hiring-manager-interview}

合格した候補者は次のステップに進みます: 行動またはシナリオベースのマネージャー面接。

このステージでは、応募しているポジションの hiring manager と会います。エンジニアリングロールの場合、これは通常 Engineering Manager です。マネジメントポジションの場合は、Senior Manager または Director になることがあります。この通話では、あなたの経験、履歴、意見に関する、より具体的で行動型の面接質問が期待できます。準備したい場合は、面接の [STAR メソッド](https://www.themuse.com/advice/star-interview-method)に慣れ親しんでおき、過去の成功事例、学び、達成について思い出しておくことをお勧めします。GitLab は文化的画一性ではなく文化的多様性を評価するため、マネージャーはカルチャーフィットではなくバリューフィットを評価します。

行動面接から 3 営業日以内にメールでフィードバックを受け取ることが期待できます。

### **5. チームメンバーとの 60 分間のピア面接** {#5-60-minute-peer-interview-with-a-member-of-the-team}

合格した候補者は次のステップに進みます: 参加を希望しているチームのメンバーとの、行動／シナリオベースのピア面接。

Engineering Manager 面接と同様に、この通話はあなたの過去の経験、背景、意見に関するさらなる議論に焦点を当てます。注目すべきは、このラウンドは自分自身の質問をし、面接を受けているロールに似た立場の人と、ここで働く日々がどのようなものかを深く掘り下げる絶好の機会だということです！

ピア面接から 3 営業日以内にメールでフィードバックを受け取ることが期待できます。

### 6. リーダーシップ面接 {#6-leadership-interview}

合格した候補者は次のステップに進みます: Senior Manager/Director/VP 面接。

ここまで来ました - おめでとうございます！これが最後の面接です。より行動型およびシナリオベースの面接質問が期待されますので、この通話の準備は前の 2 ラウンドと似たものになります。この時点では、リラックスして、このステージまで導いてくれた本当の自分でい続けるよう努めてください - 面接プロセスの最も難しい部分はすでに後ろにあります。

リーダーシップ面接から 3 営業日以内にメールでフィードバックを受け取ることが期待できます。

### 7. リファレンスチェック {#7-reference-checks}

合格した候補者はリファレンスチェックに進みます。あなたの職業上の経験について連絡を取るための 3 名の職務上のリファレンスをお願いします。

リファレンスの 1 名は、過去または現在の上司またはマネージャーであるべきです。
気が進まない場合は、現在の職場の方をリファレンスとして提供する必要はありません。
リファレンスのいずれかが英語の会話または記述に堪能でない場合は、連絡時にそれを考慮します。

長い職務経歴がない場合（例：キャリア全体で 1 つのポジションしか担っていない場合）で、いくつかのリファレンスを提供できない場合は、お知らせください。解決策を見つけるために常に対処できます。

リファレンスを提供したら、リラックスする時間です！hiring manager または採用チームがあなたが共有するリファレンスに連絡を取ります。情報を集めるのに時間がかかります。リファレンスからどれだけ早く返信があるかによります。数日連絡がなくても心配しないでください。何か障害が発生した場合は、必ずお知らせします。少なくとも週に 1 回はステータスがわかるよう、最新情報をお知らせします。

### 8. オファー {#8-offer}

合格した候補者にはその後オファーが提示されます。オファーが準備でき次第、Recruiter が連絡を取り、詳細を話し合うための Zoom コールをスケジュールします。

ご質問は？[GitLab での仕事 - よくある質問](/handbook/hiring/candidate-faq/)をご覧ください。
