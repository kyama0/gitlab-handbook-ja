### チームの目標

現在 GitLab で目標を設定・管理する方法の詳細については、社内限定の [GitLab Operating Model](https://internal.gitlab.com/handbook/company/gitlab-operating-model/) ハンドブックページを確認してください。Developer Relations の目標には、社内限定グループで [`Owner::DevRel-Strategy` ラベル](https://gitlab.com/groups/gitlab-operating-model/-/work_items?sort=created_date&state=opened&label_name%5B%5D=Owner%3A%3ADevRel-Strategy&type%5B%5D=epic&first_page_size=50)が付けられています。

### Tech Stack への追加が保留中のツール

Developer Relations チームは、Compass の [Tech Stack Update](https://app.serval.com/new-request) プロセスを通じて Tech Stack への追加が保留されているこれらのツールの DRI でもあります:

| ツール | 説明                                                                                                               | 使用方法 |
|---|---------------------------------------------------------------------------------------------------------------------------|---|
| Proxi.id | [Proxi.id](https://www.proxi.id/) は、コミュニティプログラムへの応募を自動的に審査するために使用するプラットフォームです | |

### 私たちが依存するその他のツール

以下は一部のコミュニティプログラムに不可欠なツールですが、Developer Relations チームは DRI ではありません:

| ツール名       | 説明                                                                                                                                                                                                                               | 使用方法                                                                                                                                                                                                                                                                             |
|-----------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Customer Portal | [CustomersDot](https://gitlab.com/gitlab-org/customers-gitlab-com/-/tree/staging/doc/architecture#customersdot) - 顧客がサブスクリプションとアカウント情報を管理し、GitLab ライセンスを生成・管理できる Web ポータルです。 | コミュニティプログラムへの応募に関する問題のトラブルシューティングに役立てます。コミュニティプログラムへの応募と [GitLab EE コントリビューター](/handbook/marketing/developer-relations/engineering/community-contributors-workflows/#contributing-to-the-gitlab-enterprise-edition-ee)向けのライセンスを作成・管理します。 |
| Marketo         | [Marketo](/handbook/marketing/marketing-operations/marketo/)                                                                                                                                                                              | 私たちのプログラム（[Education](https://about.gitlab.com/solutions/education/)、[Open Source](https://about.gitlab.com/solutions/open-source/)、[Startups](https://about.gitlab.com/solutions/startups/)）の各受付フォームを支えています。応募レコードを Salesforce に挿入する統合です。                                                |
| Printfection    | [Printfection](https://www.printfection.com/) は、私たちの Swag 管理プラットフォームです                                                                                                                                                             | [Printfection の使用方法](/handbook/marketing/brand-experience/merchandise-handling)                                                                                                                                                                                                |
| Salesforce      | [Salesforce](https://www.salesforce.com) は私たちの [CRM](https://en.wikipedia.org/wiki/Customer_relationship_management) です                                                                                                                     | Salesforce (SFDC) を使用して[Education と Open Source のプログラムを支援](/handbook/marketing/developer-relations/programs/)します                                                                                                     |
| Canva           | [Canva](https://www.canva.com/) は、GitLab ブランドの資料の多くを作成するために使用するツールです。                                                                                                                                       | コミュニティチームメンバーは `@gitlab.com` のメールアドレスを使用してアカウントを作成し、Design チームに[Canva Enterprise へのアクセスをリクエスト](/handbook/eta/corporate-it/end-user-services/access-requests/access-requests/)してください。                                        |

### Developer Relations のツールスタックに新しいツールを追加する

1. Compass の [Tech Stack Update](https://app.serval.com/new-request) プロセスを通じて新しいツールを追加する場合と同様に、調達プロセスに従ってください。
