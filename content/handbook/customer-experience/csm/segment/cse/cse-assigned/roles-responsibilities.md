このページでは、CSE Assigned に限定した役割とエンゲージメントの制限を示します。CSE ホームページにある一般的な [CSE DCI マトリクス](/handbook/customer-experience/csm/segment/cse/#working-with-the-account-team)を変更したり置き換えたりするものではなく、このマトリクスは引き続きそのまま適用されます。

> 以下は CSE Assigned の現時点でのガイダンスであり、CSE チームの観点のみを示すもので、厳格なモデルや最終的なモデルではありません。実際のアカウントは、必ずしも担当範囲の表にきれいに収まるわけではありません。CSE、マネージャー、アカウントチームは、このページを厳格な境界として扱うのではなく、柔軟性を保ち、顧客にとって最善の解決策に合わせて対応してください。

## 業務上の原則 {#working-principles}

- RM と AE は、引き続き契約・商談面の責任を持ち、更新に関する調整を担います。
- SA は、引き続きプリセールスからの継続性、商談の背景情報、アカウント戦略、技術的な意見の提供における重要なパートナーです。
- 担当 CSE は、技術的な兆候のプロアクティブなレビュー、目的を絞った技術的エンゲージメント、技術的エスカレーションの主導を担います。
- Duo Agent Platform（DAP）の利用定着は、CSE と SA が共同で責任を持ちます。CSE は、顧客が利用を開始した後に、利用定着と使用パターンの把握を支援します。SA は、顧客の目標に適したソリューションと利用状況を合致させる支援を行います。
- 定期的な戦略面での打ち合わせ、エグゼクティブとの認識合わせ、サクセスプランニング、広範なステークホルダー間の調整が必要な場合は、担当 CSE の範囲拡大ではなく、**専任 CSMA による支援**が必要であることを示しています。
- 範囲を定めたデリバリー作業（移行の実施、導入、アーキテクチャのパッケージ、カスタムインテグレーションの提供）が必要な場合は、担当 CSE の範囲拡大ではなく、**PS の担当範囲**であることを示しています。

## RACI：担当 CSE による支援を受ける顧客 {#raci-customers-with-assigned-cse-coverage}

*R = 実行責任者、A = 説明責任者、C = 相談先、I = 情報共有先*

| 責任 | CSE | CSE マネジメント | RM | AE | SA | PS |
|---|---|---|---|---|---|---|
| 技術的リスクと利用定着の兆候を特定する | R | A | C | I | C | I |
| 担当アカウントの技術面の健全性をプロアクティブに把握し続ける | R | A | C | I | C | I |
| 社内向けのアカウントメモに調査結果を記録する | A/R | C | I | I | I | I |
| 次に対応すべき担当アカウントの優先順位を付ける | R | A | C | I | C | I |
| 顧客への連絡前に、社内でアカウントに関する認識合わせを調整する | R | C | A | C | C | I |
| プロアクティブなエンゲージメントの前に、関係者を通じた紹介を依頼する / アカウントの背景情報を確認する | R | I | A | C | C | I |
| 技術的な状況把握、利用定着、トラブルシューティング、最適化の個別セッションを実施する | A/R | C | C | I | C | I |
| 担当アカウントの技術的エスカレーションへの対応を主導する | A/R | C | I | C | C | I |
| Duo Agent Platform（DAP）の利用状況をレビューし、利用定着の不足を特定する | R | C | I | I | R | I |
| 専任 CSMA による支援の必要性を特定する | R | C | C | A | C | I |
| 顧客が Professional Services を必要としている状況を見極める | R | I | C | R | C | C |
| 更新戦略と契約・商談面のパッケージ構成に責任を持つ | I | I | R | A | C | C |
| エグゼクティブとの認識合わせ、サクセスプランニング、定期的なビジネス上の打ち合わせに責任を持つ | I | I | C | I | C | I |
| 標準の担当範囲に対する例外や、手厚い支援の依頼を承認する | R | A | C | C | C | C |

## エンゲージメントの制限：CSE Pooled、CSE Assigned、CSMA の比較 {#engagement-limits-cse-pooled-vs-cse-assigned-vs-csmas}

担当 CSE による支援が、専任 CSMA による支援に変わることは**ありません**。標準でのケイデンスコール、EBR/QBR、カスタムワークショップ、無制限のエンゲージメントモデルは提供しません。

| アクション | CSE Pooled | CSE Assigned | CSMA |
|---|---|---|---|
| 寄せられた支援依頼に対応する | ✅ | ✅ | ✅ |
| 依頼に応じて技術的ガイダンスを提供する（範囲限定） | ✅ | ✅ | ✅ |
| 定められた担当アカウント群の技術的リスク/機会をプロアクティブに監視する | ❌ | ✅ | ✅ |
| 社内向けに定期的なヘルス情報の更新を作成する | ❌ | ✅ | ✅（アカウントプランニングであり、CSE のヘルス評価ではない） |
| エスカレーションの専任技術 DRI として対応する | ❌ | ✅ | ✅ |
| 標準で、顧客との継続的な技術面の関係に責任を持つ | ❌ | ✅（限定的、Assigned モデルの範囲内） | ✅ |
| エンゲージメントの上限 | アカウントあたり半年ごとに最大 3 ケース | アカウントあたり四半期ごとに 3 回のエンゲージメント（目安） | 上限なし（標準の実施頻度に従う） |
| 標準で定期的なケイデンスコールを実施する | ❌ | ❌ | ✅ |
| EBR / QBR を実施する | ❌ | ❌ | ✅ |
| サクセスプラン / ロードマップのガバナンス / ステークホルダー間の調整に責任を持つ | ❌ | ❌ | ✅ |
| 範囲を限定したエンゲージメントの外でカスタムワークショップを提供する | ❌ | ❌ | ✅（実施は引き続き PS/専門担当者が担う場合がある） |
| 最初の依頼が解決した後も無制限のフォローアップを継続する | ❌ | ❌ | ✅（専任担当者による支援が適用される場合） |
| 顧客が Professional Services または Success Tier を必要としている状況を見極める | ✅ | ✅ | ✅ |
| プロジェクト形式の導入作業を提供する | ❌ | ❌ | ❌（PS に移管） |
| 移行の実施 / カスタムインテグレーション / アーキテクチャのパッケージを提供する | ❌ | ❌ | ❌（PS に移管） |
| 更新に関する関係と契約・商談面に責任を持つ | ❌ | ❌ | ❌（引き続き RM/AE が担当） |

## 実務で役割の境界を判断する基準 {#practical-boundary-triggers}

**担当 CSE が引き続き対応する場合：**

- 顧客が、目的を絞った技術的な話し合いを必要としている。
- 顧客が、利用定着の障害、設定の問題、製品に関する質問を抱えている。
- 継続性が重要な技術的エスカレーションがある。
- ヘルスレビューによって、範囲を限定したエンゲージメントで対応できる具体的な技術的リスクが明らかになる。

**専任 CSMA による支援への移行を検討する場合：**

- 顧客が定期的な打ち合わせと体系的なフォローアップを期待している。
- 顧客がビジネスチームと技術チームにまたがる広範なステークホルダー間の認識合わせを必要としている。
- 顧客がロードマップのガバナンス、サクセスプランニング、定期的なエグゼクティブレビューを求めている。
- 顧客の行動から、個別の技術的対応よりも、継続的できめ細かい調整が必要であることがうかがえる。

**PS への移行を検討する場合：**

- 顧客が移行や統合の実施を必要としている。
- 顧客がデリバリー作業としてまとめられたアーキテクチャ設計を必要としている。
- 顧客がカスタムインテグレーションの設計/構築支援を必要としている。
- 顧客がマイルストーン、プロジェクト体制、導入責任者を伴う大規模な展開を必要としている。
