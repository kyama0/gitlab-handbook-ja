## 導入 - GitLab 利用統計

[GitLab Version Check](/handbook/sales/process/version-check/)を使用して、CE、EE、EE のトライアルユーザーの GitLab 利用データを Salesforce に送信します。
Salesforce アプリケーションでは、「Usage Statistics」というタブが表示されます。
ドロップダウンの表示を使って CE、EE トライアル、または EE を選ぶと、GitLab に送信されたすべての利用データを確認できます。
バージョンチェックではホスト名を取得するため、リードはホスト名で記録されます。正しい会社名を特定したら、会社名を更新してください。
例: 会社名を gitlab.boeing.com から Boeing に変更します。

利用状況を表示するには、「Usage Statistics」という列のハイパーリンクをクリックします。
リンクは a3p61012001a002 のような数字と文字で構成されます。
Salesforce のアカウントオブジェクトからも利用統計にアクセスできます。
アカウントオブジェクトの「Usage Ping Data」セクションには、同じハイパーリンクに加え、使用中のバージョン、アクティブユーザー、過去のユーザー、ライセンスユーザー数、ライセンス利用率、データの送信日に関する概要が表示されます。

利用統計から知見を得て、行動につなげる方法の例をいくつか示します。

- CE ユーザーに見込み顧客開拓を行う場合は、アクティブユーザー数で並べ替え、大規模な CE インスタンスを対象にできます。
Issue、CI ビルド、デプロイ、マージリクエスト、ボードなど、GitLab 内で何を使用しているか確認できます。
そのうえで、社内での GitLab の使い方を学び、EE でできることを伝えるために、連絡の対象を絞れます。
- ライセンスの利用数が契約ライセンス数を下回っている現在の EE ユーザーには、社内で GitLab を展開する計画と、導入をどのように支援できるかを確認できます。
- ライセンスの利用数が契約ライセンス数を超えている現在の EE ユーザーには、そのデータを使って働きかけることができます。
組織内で GitLab の導入が進んだことを祝いましょう。なぜ導入が加速したのか、どのように使っているのか（ユースケース）、追加分について今すぐ契約を変更する意向があるかを尋ねます。
トゥルーアップと新しいリニューアル額に利用量の増加が反映されるよう、リニューアル機会を更新します。
- EE の機能（たとえば CI や Issue）を使用していない現在の EE ユーザーには、その理由を確認できます。
その機能を提供していることを知っていますか？
競合製品を使用していますか？
現在のツールを GitLab と統合していますか？
現在のツールを置き換える GitLab の機能について、詳しく知りたいと思っていますか？
- EE トライアルユーザーの場合。
どの EE 機能を使用し、どの機能を使用していませんか？
EE 機能を使用している場合、何を解決・評価しようとしていますか？
使用していない場合、その理由は何ですか？ その機能を評価してみたいと思っていますか？

詳細を説明するトレーニング動画は、Google Drive の「Sales Training」フォルダーで検索してください。

## オープンソースユーザー - SFDC アカウント上の GitLab CE インスタンスと CE アクティブユーザー

[Usage/Version ping data](https://docs.gitlab.com/ee/administration/settings/usage_statistics.html)を SFDC で利用しやすくするため、Salesforce アカウントレコードの「GitLab/Tech Stack Information」セクションにあるアカウント画面に、「CE Instances」と「Active CE Users」の 2 つのフィールドを直接配置しています。

これらのフィールドの元データには、過去 60 日間に確認された各ホストの最新のバージョン Ping と利用状況のレコードを使用し、1 つのレコードにまとめます。
ホストはドメインベースと IP ベースに分けます。
IP ベースのホストでは、IP に対して[逆 DNS ルックアップ](https://en.wikipedia.org/wiki/Reverse_DNS_lookup)を行い、ドメインベースのホストに変換しようとします。
逆 DNS ルックアップ（PTR レコード）が見つからなければ、IP に対して[whois ルックアップ](https://en.wikipedia.org/wiki/WHOIS)を行い、会社名の抽出を試みます。たとえば、その IP が企業に委譲された IP アドレス範囲に含まれる場合です。
予約済み IP アドレス（内部 IP アドレス範囲）を使用している、または GCP、Alibaba Cloud、AWS などのクラウドプラットフォームでホストされているために組織を特定できないホストは、すべて除外します。このデータからは組織を特定できないためです。
ドメインベースのホストでは、Datafox および／または DiscoverOrg のドメイン検索 API を使って、その組織の会社情報と企業属性データを特定します。最後に [Google Geocoding API](https://developers.google.com/maps/documentation/geocoding/start)で住所データを可能な限り解析、整理、標準化します。

これらの統計は集計され、子アカウントがある場合は SFDC の Ultimate Parent アカウントにのみ表示されます（どのホストがどの子アカウントに属するか正確にはわからないためです）。

CE ユーザー数やインスタンス数別のアカウント一覧を表示するには、SFDC の [CE Users リストビュー](https://na34.salesforce.com/001?fcf=00B61000004XccM)を使用します。
自分のアカウントだけに絞り込むには、「edit」ボタンを押し、「My Accounts」でフィルタリングします。
元のリストを消してしまわないよう、別の名前で保存してください。
これらのフィールドは SFDC レポートでも利用できます。

このデータについて、いくつか注意点があります。

- インスタンスをできるだけ正確に SFDC アカウントに関連付けるため、組織名、ドメイン、連絡先メールのドメインに基づいてホストを対応付けていますが、ときには誤った関連付けが生じる可能性があります。
誤りや異常を見つけた場合は Data & Analytics チームに知らせてください。
- 両方のフィールドが空欄でも、その組織が CE を広く利用している可能性があります。
両方が空欄というのは、バージョンや利用状況の Ping を送信するインスタンスがないことを意味するだけで、アクティブなインスタンスが存在しないとは限りません。
- 1 人のユーザーが複数のインスタンスを利用していることもあります。そのため、組織内のいくつかのインスタンスでそのユーザーが存在し、利用状況 Ping が有効であれば、インスタンスごとに数えられます。
ユーザーが組織の外部の人である場合もあるため、ユーザー数は従業員数を表すとは限らず、従業員数より多いこともあります。
- この数値は、組織内での GitLab 利用状況の最小値と考えられます。Ping が有効なインスタンスと無効なインスタンスが混在する可能性があるためです。
バージョン Ping だけが有効な場合もあり、その場合はユーザー数を確認できません。
これを、インスタンスはあるがユーザーはいないと解釈しないでください。

これらのアカウントへの対応、サードパーティーツールからの連絡先追加、連絡方法については、ハンドブックの[ビジネスオペレーション](/handbook/business-technology/)のセクションを参照してください。
