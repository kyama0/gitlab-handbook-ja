## 背景 {#context}

MCP サーバーには、別のツールで置き換えられるツールがあります。たとえば、`get_merge_request_diffs` は、
`include: ["diffs"]` を指定した `get_merge_request` で置き換えられます。古いツールは一覧非表示ですが、そのコードは引き続き実行されます。呼び出し側は
その名前を保存します。AI Catalog エージェントは MCP ツール名を保存し、スクリプトはそれらを呼び出し、プロンプトにも名前が記載されます。エージェントは
セッション開始時に、ツールを呼び出さずに保存済みの名前を解決するため、解決できなくなった名前は
エラーなしで外されます。

## 決定 {#decision}

置き換えられるツールを、代替ツールのエイリアスにします。

- 古いコードを削除します。
- 古い名前を代替ツールの `tool_aliases` に追加し、その古い名前が意味する引数と、必要な引数名の
  変更を設定します。
- ツールは `replaced_by` で代替ツールを一度だけ宣言します。一覧からの非表示、ガバナンス上の識別情報、選択 UI は、その
  宣言を参照します。
- 古い名前を古い引数で呼び出すと、従来と同じ結果を返します。

エイリアスは呼び出しを毎回ログに記録します。呼び出しがなくなり、保存済みの
エージェントやフローのどのバージョンにもその名前が残っていなければ、
[#634007](https://gitlab.com/gitlab-org/gitlab/-/work_items/634007)（非公開）で提案されている MCP サーバーの非推奨化ポリシーに従って削除します。

## 影響 {#consequences}

- データ移行は不要です。保存済みのエージェントとフローは名前を保持します。
- 名前を保持するために、古い名前ごとに 1 つのエイリアスエントリが必要です。
- エイリアスには引数のデフォルト値と名前変更が必要ですが、MCP サーバーはまだこれらを一般的にはサポートしていません。
- ガバナンスは、代替ツールの名前とエイリアス全体で最も厳しいルールを適用します。そのため、ある側面を表す名前を拒否すると、
  代替ツール全体が拒否されます（[決定 009](009_accept_widening_under_governance.md)）。

## 検討した代替案 {#alternatives-considered}

| 代替案 | 採用しない理由 |
|---|---|
| 古い名前を削除する | データ移行でリリース済みのエージェントバージョンを書き換えなければ、保存済みエージェントがエラーなしで壊れます。Rails は、データ移行以外でのこの書き換えを拒否します。 |
| 古いコードを保持し、一覧非表示にする | 1 つの機能に 2 つの実装が残ります。これは、この作業で解消する対象です。 |
| ツールに `deprecated` フラグを付ける | `replaced_by` は同じ情報に加え、代わりに何を使うかも伝えます。 |
