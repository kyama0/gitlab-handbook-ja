## 背景 {#context}

組み込みツールは、AI Catalog エージェントが ID で選択するネイティブ DWS ツールです。目標は、DAP が GitLab
ツールを MCP サーバーから取得することなので、MCP ツールで置き換えられる組み込みツールは提供をやめ、その後に
削除すべきです。削除によって、それを使うエージェントやスクリプトが壊れてはなりません。

## 決定 {#decision}

- Rails は置き換えられた組み込みツールを一覧に載せなくなるため、選択 UI にも表示されません。
- 保存済みのエージェントは、保存時の組み込みツール ID を保持します。セッション開始時に、Rails はそれぞれを
  置き換える MCP ツールを元のツールと並べて送り、DWS は Chat と同じルールで置き換えます（[決定 002](002_pairs_in_meta.md)、
  [決定 003](003_origin_rule.md)）。
- エージェントの次のセッション以降、そのエージェントを編集できるすべての人に、エージェントの
  ページ上で置き換えに関する通知を表示します。置き換えられた ID を保存する API リクエストには、代替ツール名を含む警告を返します。誰も承認する必要はありません。
  通知の見た目は未定です（[カスタムエージェントの未解決の疑問](../consumers/ai_catalog_custom_agents.md#open-questions)）。
- DWS は、MCP ツールを配信しない GitLab バージョンにサービスを提供する限り、Python ツールを保持します。

## 影響 {#consequences}

- 保存済みのエージェントバージョンは書き換えません。
- 所有者が何も対応しないエージェントも MCP ツールに移行するため、ネイティブツールの削除を妨げません。
- MCP ツールが届かないセッションでは、Chat と同じくネイティブツールを保持します。
- 各ペアには入力スキーマの確認が必要です。MCP ツールとネイティブツールの引数の違いが
  呼び出しを壊す場合、そのペアを有効にする前に引数のマッピングが必要です。
- DWS からの Python ツールの削除は、それを必要とするサポート対象の GitLab バージョンがなくなるまで待ちます。

## 検討した代替案 {#alternatives-considered}

| 代替案 | 採用しない理由 |
|---|---|
| 組み込みツールを MCP ツールと並べて引き続き提供する | DAP は 1 つの作業に 2 つのツールを提供し続けます。 |
| ユーザーに知らせずにツールを置き換える | 所有者が知らないうちにエージェントのツールが変わります。 |
| 所有者が置き換えを 1 件ずつ承認する | 所有者が何も対応しないエージェントにはネイティブツールが残るため、削除できなくなります。また、API には承認を求める手段もありません。 |
| セッション開始前に Rails がツールを置き換える | Rails は MCP ツールが届くかを判断できないため、届かないセッションにはどちらのツールもなくなります。 |
